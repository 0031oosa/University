# ТЗ: конвейер сбора и обезличенной аналитики открытых дроп-реквизитов

> Документ предназначен как спецификация для реализации (в т.ч. через Claude Code)
> и как основа отчёта по производственной практике магистратуры «ИИ и МО».

## 1. Контекст и цель

Тема: «Сбор и аналитика открытых индикаторов платёжного мошенничества
(дроп-реквизитов) для задач антифрод-детекции».

Источник данных — публичные страницы ресурса `platshield.com`, раздел «P2P-дропы»:
публикуемые списки номеров карт и телефонов СБП, фигурирующих в расчётах
нелегального гемблинга.

Цель — программный конвейер **сбор → нормализация → обезличенное хранение →
агрегатная аналитика**, пригодный как основа исследовательского датасета для
последующей детекции счетов-посредников («мулов») методами ML.

Ценность работы — не дамп реквизитов, а **структурирование, обогащение признаками
и обезличивание** + агрегатная аналитика.

## 2. Обязательные ограничения (hard constraints — не опциональны)

Это критерии приёмки, а не пожелания:

1. **Только публичные страницы.** Никакого обхода авторизации, капчи, rate-limit
   и иных технических ограничений. Если раздел требует логина — он вне scope.
2. **robots.txt соблюдается**, частота запросов ограничена (≥2 c пауза),
   экспоненциальный backoff, честный User-Agent с контактом.
3. **152-ФЗ.** Сырые реквизиты (полный PAN, полный телефон) хранятся только
   локально. Во все логи, выгрузки для отчёта и графики попадают ТОЛЬКО
   маскированные (`220220******1234`, `+7(910)***-**-67`) или агрегированные
   значения. Инструмент не перепубликует и не передаёт ПДн третьим лицам.
4. Постановку («сбор + обезличенная аналитика», не «выгрузка живых номеров»)
   согласовать с научным руководителем до реального сбора.

## 3. Функциональные требования

### 3.1 Модуль сбора (`scraper.py`)
- Класс `PoliteFetcher`: загрузка страниц с учётом robots.txt, троттлингом,
  backoff, повторами.
- Разбор HTML-таблиц через BeautifulSoup. Селекторы и алиасы колонок вынести
  в конфиг (`SELECTORS`, `COLUMN_ALIASES`) — разметку подгоняет пользователь.
- Устойчивость к отсутствию `<th>`: колонки по позиции как fallback.

### 3.2 Нормализация
- Валидация карты по алгоритму Луна.
- Выделение БИН (первые 6 цифр) и грубое определение платёжной системы
  (VISA / Mastercard / МИР / AmEx) по диапазонам. Предусмотреть подключение
  внешней БИН-базы для точной атрибуции банка.
- Приведение телефонов к `+7XXXXXXXXXX`.

### 3.3 Хранение
- SQLite, дедупликация по паре `(card, phone)`.
- Экспорт в CSV **только в маскированном виде** (для отчёта).

### 3.4 Аналитика (`analyze.py`)
- Агрегаты: распределение по платёжным системам, топ-банков, по операторам СБП
  (по префиксу телефона), динамика пополнения во времени.
- Графики (matplotlib, Agg) в `report_assets/`. Никаких сырых PAN/телефонов
  в выводе.
- Режим `--demo`: генератор синтетических данных (Luhn-валидные фейковые номера)
  для воспроизводимого прогона без реальных ПДн.

## 4. Нефункциональные требования
- Python 3.10+, зависимости: `requests`, `beautifulsoup4`, `matplotlib`.
- Модульность, type hints, docstrings на русском (деливери для рус. вуза).
- CLI через `argparse`. Воспроизводимость демо (фиксированный seed).

## 5. Артефакты проекта
```
scraper.py          — сбор + нормализация + хранение + маскирование
analyze.py           — аналитика + графики + генератор демо-данных
requirements.txt
README.md           — запуск + раздел про ответственное обращение с данными
report_assets/      — сгенерированные графики
Отчёт_по_практике.docx
```

## 6. Структура отчёта (ГОСТ Р 15.101-2021)
Титульный лист · Реферат (с ключевыми словами) · Содержание · Введение
(актуальность: 115/161-ФЗ, антифрод) · 1 Аналитический обзор (дропперство и
P2P-процессинг; открытые источники и их ограничения; ML в антифроде) ·
2 Постановка задачи · 3 Проектирование и реализация (архитектура; политика
обхода; нормализация; хранение и обезличивание) · 4 Экспериментальная часть
(методика на синтетике; результаты с 4 рисунками) · Заключение · Список
источников.

Оформление: Times New Roman 14, интервал 1.5, выравнивание по ширине, поля
(лево 3, право ~1.5, верх/низ 2 см), нумерация страниц, оглавление автополем.

## 7. Критерии приёмки
- [x] Демо-прогон `python analyze.py --demo` строит 4 графика без ошибок.
- [x] В любом выводе (логи/CSV/графики) отсутствуют полные PAN и телефоны.
- [x] robots.txt учитывается; нет обхода авторизации.
- [ ] Отчёт собирается, графики встроены, оглавление обновляется в Word.

## 8. Порядок работы для Claude Code
1. Начать с `analyze.py --demo` + `scraper.py` на синтетике — убедиться, что
   пайплайн и маскирование работают до любого реального запроса.
2. Реализовать нормализацию и тесты на неё (Луна, БИН, телефоны, маскирование).
3. Только потом — реальный сбор с подгонкой селекторов под фактическую разметку.
4. Собрать отчёт (docx-js), встроить графики из `report_assets/`.

### Примечание по robots.txt (проверено 2026-07-13)
`https://platshield.com/robots.txt` явно запрещает обход для `User-agent:
ClaudeBot` (`Disallow: /`) и помечает `Content-Signal: ai-train=no`. Общий
`User-agent: *` разрешён, кроме `/admin/` и `/api/`. Из-за прямого запрета
для ClaudeBot Claude Code не выполнял и не должен выполнять запросы к
реальным страницам сайта от своего имени — это входит в противоречие с
п.2 ограничений. Реальный сбор — только через `scraper.py`, запущенный
пользователем с честным собственным User-Agent, после согласования
постановки с руководителем и подгонки `SELECTORS`/`COLUMN_ALIASES` под
фактическую разметку.
